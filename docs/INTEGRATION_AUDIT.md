# Integration audit — 23 October 2026

Audit baseline: local application commit `4a89e82`, branch `lingareddy-dhanush`. Training workspace is the parent directory; it is not part of this application repository. This document records inspected behavior before this phase's implementation. No retraining, model replacement or checkpoint deletion is required.

## Existing application

React 19 / TypeScript / Vite lives in `frontend/`. `src/App.tsx` coordinates authentication, cases, uploads and analysis using component state/effects, with role workspaces, `AnalysisWorkbench.tsx`, `AnalysisHistory.tsx`, `ModelWorkspace.tsx` and `ReportsPage.tsx`. No separate frontend model implementation is needed.

FastAPI lives in `backend/app/main.py`; SQLAlchemy models and sessions are in `models.py` and `database.py`. SQLite is the local default; PostgreSQL is configurable. Password hashing, JWT sessions and identities are in `security.py` and `auth_ext.py`. Roles include doctor/clinician, researcher, ml_engineer, administrator, technician and viewer. Backend checks combine role, operational action grants and case ownership/assignments. Administrators do not automatically own every case. Two existing policy tests fail; resolving their intended policy requires a separate decision, not a silent permission expansion.

Uploads are capped at 50 MiB, decoded by content and stored under generated IDs outside public static files. `preprocessing.py` handles raster images, selected DICOM frames and PDF pages. `volume_preprocessing.py` handles bounded scalar 3D preparation with spacing/orientation. `case_contract.py` restricts current inference to coronary XCA; CT/CTA/MRA support preparation/export only. Modality is operator-declared, not automatically inferred. DICOM tag checks are safeguards, not proof of full de-identification or absence of burned-in identifiers. Manual de-identification review remains necessary. Current storage retains original filenames as metadata; they must not contain identifying information.

`AnalysisRun` holds the latest result; immutable `AnalysisEvent` entries retain reruns. Overlays and measurement sidecars live under private `storage/analysis/`; artifact routes check case access. Report revisions snapshot analyses and separate clinician reviews. The current POST `/api/images/{id}/analyze` blocks until inference completes. There is no persistent inference job table/worker yet. Existing training/execution actions must stay separate from upload/inference.

## Verification and configuration

`backend/requirements.txt` provides the API/imaging stack; `requirements-ai.txt` provides optional Torch/Torchvision/OpenCV/SciPy. Installed two-mask release loads without pretrained downloads. Secrets belong in ignored `backend/.env`; checkpoints, archives, databases, uploads and venvs are excluded from Git. Frontend production build passes. Prior source-to-app parity on one development frame is bit-identical for both models. Latest pre-phase backend suite: 61 passed, 1 skipped, 2 pre-existing permission-policy failures with installed-model tests enabled. This is integration evidence, not fresh model performance or target-laptop acceptance.

## Recommended incremental changes

Preserve the current adapters, API authorization, history and UI. Add persistent bounded single-worker inference jobs with explicit failures/restart policy, a validated versioned result document, candidate coordinates in the saved prepared-image frame plus source mapping, private raw mask/score artifacts, and deterministic explanations. Keep unsupported 3D/severity/LLM/training controls explicitly unavailable. Verify synthetic and installed-checkpoint paths before claiming completion.
