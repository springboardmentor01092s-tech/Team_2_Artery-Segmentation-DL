# CoroVision AI — repository-specific master integration prompt

Use this prompt with the application checkout and a separately accessible training artifact directory. Read the four audit documents first; they distinguish implemented features from proposals and unavailable evidence.

> Work in the existing CoroVision AI repository. The only publishing branch is `lingareddy-dhanush`; never push main/master. Respect AGENTS.md. Keep training code/execution in the separate training workspace and weights/datasets/secrets outside Git. Do not retrain, replace architectures, overwrite checkpoints, enable rejected candidates or publish clinical claims to make integration appear complete.
>
> First inspect `docs/INTEGRATION_AUDIT.md`, `docs/MODEL_REGISTRY.md`, `docs/END_TO_END_WORKFLOW.md`, `docs/INTEGRATION_PLAN.md`, the actual frontend/backend source, existing tests and current Git state. Reconcile them with `ml/releases/corovision_20261023.json`, `ml/releases/research_evidence_20261023.json` and the external training inventory/configuration/evaluation reports. Update the four audit documents before further major changes. Never assume an architecture in a design document exists or is validated.
>
> Reuse the existing React/TypeScript/Vite application, FastAPI API, SQLAlchemy persistence, JWT/session security, operational grants and case assignments. Clinicians/researchers use authorized research cases and de-identified uploads; clinicians review and approve report revisions where granted. ML engineers inspect separate task evidence and governed model registrations. Administrators manage accounts/grants/operations without bypassing case access or editing saved predictions. Preserve technician/viewer restrictions. Do not resolve existing contradictory permission tests by silently weakening authorization.
>
> Implement and verify the dependency graph: authenticated case → upload validation/confirmed modality → recorded preprocessing → compatible approved artery mask → mask QC → deterministic vessel graph/measurements where meaningful → compatible stenosis mask candidates → optional verified vessel association → conditional severity → versioned saved result → deterministic evidence explanation → viewer/history/report/review. Do not modify an image-only stenosis model to accept centerlines or mask channels without a separately validated model change. Unsupported association/3D/severity stages must explain why they are unavailable.
>
> Use `backend/app/trained_release.py` and the two pinned preserved coronary XCA baselines. Verify artifact hashes before loading, preserve exact normalization/resizing/thresholds and class mappings, keep raw scores distinct from calibrated probabilities, and fail closed on missing/corrupt artifacts or incompatible modality/anatomy. Artery output is binary union; ARCADE stenosis output is instance masks with source category 26. Archive lesion boxes, CADICA grades, anatomical instances, DCA, aorta/hepatic CT and ImageCAS/ImageCAS-X CTA are separate tasks. Their research metrics do not approve them for this endpoint. Do not substitute lesion boxes for masks or CT anatomy for coronary XCA.
>
> Keep original, prepared and volume coordinate systems explicit. Record ROI, resize/padding, selected frame/page, input hashes and spacing/orientation. Predictions currently live in the prepared 512-square frame; map candidate mask bounds back using the saved transform and mark clipping/padding. Do not imply a full original-resolution segmentation or a whole-study finding from one frame. A non-square/DICOM/PDF/enhanced upload is outside the existing single-development-frame parity example; display this limitation. Raw arrays remain in private authorized artifact storage, not database JSON.
>
> Use persistent idempotent analysis jobs. POST returns a job ID immediately; frontend polls/resumes saved status, shows failure and preserves prior runs. Recheck grants, case access, input integrity and pinned model version at execution. Do not silently retry an interrupted job or duplicate an active image job. Current deployment supports one API process and one in-process inference worker; queued requests expire after 30 minutes and interrupted processing fails on restart. Multi-process/external workers and a hard per-job process timeout require separately tested isolation/leases; do not claim those exist.
>
> Authoritative results use `corovision.result.v1` with IDs, checkpoint hashes, input transformation, artifacts, stage statuses/reasons, measurements/units, candidate IDs/locations/raw score semantics, quality warnings, validation split/aggregation and review status. Reject non-finite values. Freeze history to the event's original evidence. Human review and generated explanation must not modify numerical predictions. Old events without a structured result stay historical; do not fabricate or rebind them to current weights.
>
> Reuse deterministic mask-derived centerline/branch/connectivity/length/diameter/tortuosity algorithms. They are 2D projection estimates; pixels are not millimetres without calibration and projected area is not a vessel cross-section. Empty masks skip meaningful vessel measurements. A valid spacing value alone does not validate segmentation or stenosis severity. Global mask diameter percentiles and mask area ratios cannot supply a candidate-local stenosis reference.
>
> Severity must return `insufficient_evidence` with null percentage/category while validated local/reference diameter selection and a permitted reference standard are absent. Only after those prerequisites are validated may a measurement module calculate `(D_reference-D_minimum)/D_reference*100`, reject invalid values and apply explicitly validated task-specific categories. Dataset grade strings and uncalibrated model scores are not clinical severity. “No candidate detected by this model” never means healthy.
>
> Explanations must derive from the saved structured object. Use deterministic source-linked sections for summary, artery mask, vessel measurements, candidates, severity and limitations. Values/units/versions must match persistence; missing fields remain missing. Validation scores describe their dataset/split, not accuracy on the uploaded image. No language model should independently diagnose the image or invent locations, numbers or confidence. If an optional LLM is later configured, constrain/validate it against the same source and retain deterministic fallback.
>
> Reuse the existing authorized overlay/centerline/history/report UI. Display persistent job state and saved explanations/candidate coordinates in both workbench and research report. Preserve historical results on reruns. Confirm source/overlay alignment manually on a permitted representative image and verify all protected result/artifact URLs reject an unrelated user. Never enable a fake training action or upload-triggered training.
>
> Test each stage before proceeding. Include content/size/corruption/route/spacing cases, checkpoint load/parity, geometry and class mapping, idempotency/history, restart/failure/revoked access/input tampering/model changes, private mask/raw-score downloads, null severity and explanation field references. Run the existing regression suite and frontend build; separate pre-existing failures from regressions. Synthetic inference checks plumbing, not clinical performance. Record commands, exact results, source commit, changed files, blockers and target-laptop/manual acceptance still required. Do not claim all phases complete because source files or an offline training score exist.

Deployment and current phase results: `docs/TRAINED_RELEASE_INTEGRATION.md` and `reports/end_to_end_integration.md`. Large artifacts transfer separately using `scripts/install_trained_release.py`. GitHub access failures are external blockers; retain local commits rather than bypassing permissions.
