# Local demonstration

Run `python scripts/run_local.py` from the application root to serve the built frontend and API on loopback at `http://127.0.0.1:8000/`. A separate Vite development frontend can use port 5173. Opening the application does not start training.

On an isolated demo installation with seeded users and `CV_LOCAL_DEMO_SESSIONS=1`, open `http://127.0.0.1:8000/?demo_role=researcher` to select the researcher. The app removes the role selector from the URL after selection. The backend only issues roster sessions when both the request host and peer are loopback and production mode is off. Other role values are `clinician`, `doctor`, `ml_engineer`, `technician`, `viewer` and `admin`. Existing case access and grants still apply.

The local researcher has a case named `DEMO-INTEGRATED-SYNTHETIC`, containing a generated geometric PNG and a completed persistent analysis job using the pinned artery and stenosis-mask checkpoints. It is synthetic demonstration data, not a patient example or performance validation. Open AI Analysis to inspect its saved masks, centerline, raw scores, stage status and explanation. Automatic severity remains insufficient_evidence. No other user's cases were shared with the demo team.

Direct dashboard navigation accepts `case_id`, `image_id` and `run_id` query parameters alongside the local `demo_role` selector. An exact saved-run link restores the authorized case, image and run after refresh. An inaccessible case does not grant access. On the saved AI overlay, candidate bounds and their raw scores are shown by default when present. The saved explanation and candidate details are below the viewer. IDs refer to the installation's database. Public validation cases provide development evidence.

Missing accounts can be created using the existing idempotent seeder from `backend/` with the application's Python environment: `python seed_demo_accounts.py`. Windows now skips the unavailable POSIX fchmod call; credential files inherit the backend directory's Windows access controls. Existing passwords are preserved. Generated passwords remain in ignored `backend/demo-credentials.json`; do not publish that file. The existing demo roster endpoint issues demonstration sessions, so this configuration is for an isolated local demonstration, not public hosting.
